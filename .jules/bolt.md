## 2024-05-22 - Optimize Bulk Operations with ListSerializer
**Learning:** Overriding DRF's `ListSerializer.create` method and utilizing PostgreSQL's native `bulk_create` with `update_conflicts=True` substantially reduces execution time for bulk insertions (e.g., from ~0.8s to ~0.03s for 1000 items) by eliminating the N+1 database queries inherent to standard DRF `update_or_create` iterative calls within loops over serialized data.
**Action:** When dealing with DRF bulk insertions (like a serializer initialized with `many=True`), override `ListSerializer.create` to use native `bulk_create(update_conflicts=True)` instead of iterative `update_or_create` calls, to prevent severe N+1 database performance bottlenecks. Instantiate Django models using dictionary unpacking on validated data items.
