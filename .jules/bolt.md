## 2024-07-04 - Overriding ListSerializer.create to optimize bulk_create
**Learning:** DRF`s default ListSerializer implementation of `create` iteratively calls `create` on the child serializer for each item. When the child serializer`s `create` uses `update_or_create` (like ContactosSerializer), it leads to an N+1 query bottleneck during bulk insertions (2 queries per item + transaction management). Overriding `ListSerializer.create` and utilizing PostgreSQL`s `bulk_create(update_conflicts=True)` reduces the total DB operations to 1 query regardless of array size.
**Action:** Always check if a DRF serializer handles bulk data (`many=True`). For bulk updates/inserts, use `bulk_create(update_conflicts=True)` instead of iterative ORM calls to solve N+1 problems. Overriding the meta class list serializer is key to implementing this.
