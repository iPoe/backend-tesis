## 2024-05-24 - Bulk Insert Optimization in Django REST Framework
**Learning:** `ContactosSerializer` executes an O(N) database query pattern by running `update_or_create` inside a loop when `many=True` is provided to `ContactosSerializer(data=dcontactos,many=True)`. Each `.save()` inside the loop runs multiple DB queries.
**Action:** When overriding serializers with `many=True`, use a `ListSerializer` subclass, and override the `create` method to perform `bulk_create(update_conflicts=True)` instead of executing individual `update_or_create` per item.
## 2024-05-24 - Data deduplication before bulk DB insert with conflicts handling
**Learning:** `bulk_create(update_conflicts=True)` maps to PostgreSQL's `ON CONFLICT DO UPDATE`. When executing this on data that contains duplicate records with the exact same unique key in a single batch, the database crashes with an `IntegrityError` or `ProgrammingError` ("ON CONFLICT DO UPDATE command cannot affect row a second time"). The original `update_or_create` loop in DRF handled duplicates naturally because later iterations updated the record created by earlier ones.
**Action:** Always deduplicate incoming `validated_data` using the unique key (e.g., `deduped_data = {item['identidad']: item for item in validated_data}.values()`) before mapping the items to Django models and invoking `bulk_create(update_conflicts=True)`.
