## 2024-05-09 - DRF Bulk Create and update_conflicts
**Learning:** Overriding `serializers.ListSerializer.create` to use PostgreSQL's native `bulk_create(update_conflicts=True)` turns N+1 inserts into a single O(1) query. Also, be sure to note that if DRF uniqueness validators are disabled on the child serializer (e.g., `validators: []` on the `identidad` field), failing to handle upsert properly will cause an unhandled 500 error, so `update_conflicts=True` works perfectly as an upsert that ignores those constraints and cleanly updates the records.
**Action:** Anytime a DRF bulk endpoint causes a bottleneck (e.g. `many=True` in a serializer initialization), implement a `ListSerializer` utilizing `bulk_create(update_conflicts=True)` instead of allowing iterative `update_or_create` calls, provided PostgreSQL is the backend.
